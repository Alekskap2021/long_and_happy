# Дизайн-система «Долго и счастливо»

Реализация ТЗ из `docs/tz-redesign.md`. Здесь то, что уже лежит в коде: токены, палитры, компоненты, motion и правила вёрстки. Документ — источник правды для новых страниц.

---

## 1. Направление

**Выбранное направление: «Пауза».** Не «психологический wellness», а атмосфера внимательного разговора: много воздуха, крупная типографика, мягкие плоскости вместо карточек, реплики набраны отдельным «голосом».

Три решения, которые держат стиль:

1. **Бренд крупнее заголовка.** На первом экране «Долго и счастливо» набрано в `text-brand` (до 6.5rem). Заголовок блока — `text-title`, он не спорит с брендом.
2. **Реплика — это другой шрифт.** Всё, что человек говорит (сцены тем, вопросы диагностики, голоса авторов), набрано `voice` — Literata italic. Разбор и интерфейс — гротеск. Так «два слышания» видно, а не только читается.
3. **Карточек нет.** Списки — это строки с отступами и подсветкой при наведении (`ListLink`). Поверхность (`Panel`) появляется только там, где без неё ломается взаимодействие: фильтры, сценарий диагностики, форма.

Чего сознательно избегаем: фиолетовых и indigo-градиентов, шаблонного cream + terracotta + serif, газетной сетки с плотными колонками и hairline-линейками, стоковых «счастливых пар», таймеров и искусственного дефицита.

## 3. Цветовые токены

Цвет живёт только в CSS-переменных в `src/app/globals.css`. В компонентах — семантические имена (`bg-paper`, `text-ink-soft`, `border-line`), сырых hex в JSX нет. Значения заданы в **OKLCH**: светлота задаётся напрямую, поэтому контраст переносится между палитрами предсказуемо.

| Группа | Токены |
| --- | --- |
| Поверхности | `paper`, `paper-deep`, `paper-card`, `elevated`, `surface-hover` |
| Текст | `ink`, `ink-soft`, `ink-muted` |
| Линии | `line`, `line-strong`, `line-hover` |
| Акцент | `accent`, `accent-hover`, `accent-soft`, `accent-quiet`, `accent-edge`, `on-accent` |
| Вторичный акцент | `second`, `second-soft`, `second-quiet` |
| Смысловые | `boundary`, `boundary-soft` (янтарь, не «алая тревога») |
| Инвертированная полоса | `band`, `on-band`, `band-line`, `band-accent`, `band-quiet` |
| Фокус | `ring` |

**Производные состояния не рисуются вручную.** `surface-hover`, `line-hover`, `accent-quiet`, `accent-edge` считаются через `color-mix(in oklab, …)` от базовых токенов палитры: меняется палитра — пересчитываются состояния.

**Инвертированные полосы.** Утилита `band-scope` переопределяет токены для поддерева, поэтому кнопки, теги и текст внутри тёмной полосы подстраиваются сами — вариантов «для тёмного фона» в пропсах компонентов нет.

Две ловушки, из-за которых полоса тихо ломается:

- **Токен нельзя вычислять от самого себя.** `--second: color-mix(…, var(--second), …)` внутри `band-scope` — это цикл: по спецификации свойство становится невалидным, цвет уходит в `currentColor`, и текст сливается с фоном. Поэтому светлые версии для полосы объявлены в палитре отдельными именами (`--band-accent`, `--band-second`, `--band-boundary`), а `band-scope` только подставляет их.
- **В своём CSS используем смысловые токены, а не `--color-*`.** Переменные `--color-…` из `@theme inline` вычисляются на `:root` и не следуют за `band-scope`; утилиты Tailwind подставляют значения инлайном и работают правильно. В `prose-editorial`, `::selection` и `:focus-visible` пишем `var(--ink-soft)`, `var(--accent)`, `var(--ring)`.

**Пары контраста.** Замеряются скриптом на всех палитрах (в том числе внутри `band-scope`) переводом вычисленного цвета в sRGB через canvas — `getComputedStyle` отдаёт `lab()`/`oklab()`, парсить его руками нельзя. Текущий минимум по всем парам — 4.5:1, ни одной пары ниже:

| Пара | Требование | Факт (худшая палитра) |
| --- | --- | --- |
| `ink` на `paper` | ≥ 7:1 (AAA для основного текста) | 15.3 |
| `ink-soft` на `paper` / `paper-deep` | ≥ 4.5:1 | 6.5 |
| `ink-muted` на `paper` / `paper-deep` | ≥ 4.5:1 (только мелкие подписи) | 4.7 |
| `on-accent` на `accent` | ≥ 4.5:1 (текст кнопки) | 5.3 |
| `accent` на `paper` / `accent-quiet` | ≥ 4.5:1 (ссылки, акцентный текст) | 4.5 |
| `on-band` на `band` | ≥ 7:1 | 13.0 |
| `boundary` на `boundary-soft`, в полосе тоже | ≥ 4.5:1 | 5.5 |

## 4. Палитры и переключатель

Девять палитр, одинаковый набор токенов, разные настроения. Реестр — `src/lib/themes.ts`, значения — `[data-theme="…"]` в `globals.css`.

| id | Название | Схема | Настроение |
| --- | --- | --- | --- |
| `pause` | Пауза | светлая | холодная бумага, глубокий петроль, латунь — тема по умолчанию |
| `paper` | Бумага | светлая | тёплая бумага, глина, лес — продолжение первого языка сайта |
| `conifer` | Хвоя | светлая | прохладная зелень и охра, самая тихая |
| `pastel` | Пастель | светлая | кремовая бумага, оливковый акцент, терракота во втором |
| `dried` | Сухоцвет | светлая | винный акцент, шалфей, сиреневая дымка в мягких плоскостях |
| `studio` | Студия | светлая | почти белый свет, шалфей, тёплый беж и тёмное дерево |
| `bordo` | Бордо | светлая | бумага и чернила, винный акцент, старое золото в полосе |
| `dusk` | Сумерки | тёмная | глубокая синяя, абрикосовый акцент |
| `coal` | Уголь | тёмная | тёплая почти-чёрная, приглушённый розовый |

Светлые палитры от «Пастели» и дальше собраны с референсов, и правило переноса там одно: с картинки берётся 2–4 цвета на роли `accent`, `second` и бумагу, а остальной ряд (чернила, линии, полоса, светлые версии для `band-scope`) достраивается по светлоте до контраста AA. Пастельный цвет из референса почти никогда не годится как есть: `#CF7D65` на кремовой бумаге даёт около 2:1, поэтому его тон уходит в `second` с посаженной светлотой, а исходный оттенок остаётся жить в `band-second` и мягких тинтах.

В «Бордо» точно по референсу перенесены бумага `#F3EFE7`, чернила `#202322` и вино `#762D3A` (акцент). Остальные три цвета сдвинуты по светлоте под роли: серо-зелёный `#667166` в `second` посажен до 50%, иначе текст тега на `second-quiet` даёт 3.9:1; старое золото `#B39A6A` слишком светлое для текста, поэтому в `boundary` оно углублено до 49.5%, а исходный оттенок живёт в `band-accent` и `band-boundary`; сине-серый `#7A8790` ушёл в `line-strong` и `band-second`. Полоса не берёт вино как есть: на `band` 40.5% приглушённый текст (`ink-muted` — 60% примеси `on-band`) даёт 3.96:1, поэтому фон полосы углублён до 33%, где та же пара держит 4.75:1.

Девять пунктов уже не влезают на короткий экран, поэтому в переключателе список ограничен `max-h-[var(--available-height)]` от позиционера Base UI и скроллится внутри, а подпись «Палитра» остаётся на месте.

Логика переключения:

- атрибут `data-theme` на `<html>` — единственный источник правды; React читает его через `useSyncExternalStore`, а не хранит копию в состоянии, поэтому нет ни рассинхрона, ни `setState` в эффекте;
- выбор хранится в `localStorage` (`lah-theme`), событие `lah:themechange` и `storage` синхронизируют переключатели, в том числе между вкладками;
- инлайн-скрипт из `themeBootstrapScript` выполняется **до первой отрисовки** — вспышки чужой палитры нет;
- если выбора ещё не было, тема берётся из `prefers-color-scheme` (тёмная система → «Сумерки»);
- каждая палитра объявляет `color-scheme`, поэтому системные элементы (скроллбары, контролы) не выпадают из темы;
- `meta[name="theme-color"]` обновляется под текущий фон: берём вычисленный `background-color` у `body`, потому что браузер отдаёт его в `rgb()`, а значение самого токена осталось бы `oklch()`/`lab()`;
- UI переключателя — Base UI `Select` (`src/components/theme/theme-switcher.tsx`) в шапке и подвале. Превью палитры рисуется элементом с `data-theme`, поэтому в переключателе нет ни одного сырого цвета.

Иллюстрации живут в той же палитре: они векторные и заливаются токенами (см. §6).

## 5. Motion: три приёма, больше не добавляем

| Приём | Триггер | Свойства | Длительность / easing | reduced-motion |
| --- | --- | --- | --- | --- |
| **Появление блока** (`Reveal`, утилита `reveal`) | первое попадание в кадр, один раз | `opacity` 0→1, `translateY` 10px→0 | 320ms, `--ease-calm` | без сдвига, `opacity` 160ms linear |
| **Смена кадра шага** (`animate-step-in`) | смена шага диагностики и показ результата | `opacity` + `translateY` 6px | 320ms, `--ease-calm` | анимация выключена (`motion-reduce:animate-none`) |
| **Отклик интерактива** | hover / focus / выбранный вариант / открытие попапа | `background-color`, `border-color`, `color`, `opacity`, `transform` попапа | 150–260ms, `--ease-calm` | `motion-reduce:transition-none` |

Правила:

- прогресс диагностики двигается тем же easing (`transition-[width] duration-320`);
- попапы Base UI анимируются CSS по `data-starting-style` / `data-ending-style`, без JS-таймлайнов;
- `Reveal` переключает атрибут `data-visible` прямо на узле из `IntersectionObserver`: анимация живёт в CSS, состояние React для неё не нужно и лишних рендеров нет;
- блоки прячутся до появления **только если** на `<html>` стоит `data-motion="on"` — атрибут ставит инлайн-скрипт при живом JS и обычной настройке движения. Без JS и при `prefers-reduced-motion` контент читается сразу;
- запрещено: параллакс, бесконечный float, glow-пульсации, typewriter, scroll-jacking, анимация каждой карточки в списке.

## 6. Иллюстрации и фоны

- Иллюстрации — **вектор на токенах** (`src/components/ui/illustration.tsx`), не растр: при смене палитры графика меняется вместе с интерфейсом. Абстракция, без лиц и надписей.
- Смысловая часть (alt, подпись) остаётся контентом: `src/content/data/illustrations.ts`. Ключи (`dialog-loop`, `money-pair`, `seven-steps`, `method-core`, `divergence`, `library`) и роли сохранены.
- Роли: `band` — широкая передышка в длинном тексте, `block` — иллюстрация в колонке, `thumb` — узкая полоса-превью.
- Холст всех рисунков — 1200×700, кадр обрезается по `preserveAspectRatio="slice"`. Поэтому пропорции вариантов считаны от холста: `block` — ровно `12/7` (композиция видна целиком), `band` и `thumb` — осознанная обрезка. Фигуры держим внутри холста: то, что нарисовано на срезе края, в маленьком кадре читается как случайно разрезанное пятно.
- Крупные заливки — полупрозрачные (0.44–0.5) и с тонким контурным кругом рядом: сплошные пятна на всю секцию выглядят как баннер, а не как передышка.
- `BackdropArt` — та же графика как фоновая плоскость: позиционируется вызывающей стороной и должна выходить за край экрана, а не сидеть в рамке.
- `HeroArt` — якорь первого экрана: два полупрозрачных круга (одна сцена, два слышания) без blend-режимов, поэтому композиция читается и в тёмных палитрах.
- Фон секций не плоский: утилиты `wash` / `wash-quiet` (два пятна от акцентов + вертикальный градиент) и `grain` (зерно на `feTurbulence`).
- Единственный растр на сайте — портрет авторов.

## 7. Компоненты: Base UI против обычной вёрстки

Base UI (`@base-ui/react`) отвечает за поведение и доступность, внешний вид — наши классы на токенах.

| Паттерн | Решение |
| --- | --- |
| Мобильное меню | Base UI `Dialog` (focus trap, Esc, блокировка прокрутки) |
| Переключатель палитры | Base UI `Select` |
| Фильтры библиотеки | Base UI `Toggle Group` (клавиатура, `data-pressed`) |
| Варианты ответа в диагностике | Base UI `RadioGroup` + `Radio` (стрелки, `data-checked`) |
| Поля форм и ошибки | Base UI `Field` (связка label/control/error, `data-invalid`) |
| Прогресс диагностики | **исключение:** `div` с `role="progressbar"` — примитив не даёт ничего сверх этого |
| Секции, editorial-текст, списки материалов | обычная вёрстка, без обёрток «на всякий случай» |

Публичный API обёрток стабилен: страницы импортируют `Button`, `ButtonLink`, `Field`, `Tag`, `Note`, `Panel`, `ListLink`, `Section`, `PageHeader`, `Reveal`, `Illustration` — и не тянут Base UI напрямую.

Для попапов в `globals.css` заданы обязательные для Base UI вещи: `isolation: isolate` на `.app-root` и `position: relative` на `body`.

## 9. Правила вёрстки страниц

1. Одна секция — одна задача: надзаголовок, заголовок, одна поддерживающая фраза.
2. Первый экран главной: бренд, заголовок, фраза, одна группа CTA, одна плоскость. Никакой статистики, расписаний, отзывов и промо-чипов.
3. Длинный текст — `prose-editorial` в колонке до ~40rem, с иллюстрацией-передышкой в середине.
4. Список — `ListLink` в отрицательных внешних отступах (`-mx-5 sm:-mx-6`), чтобы текст строки был на одной линии с заголовком секции.
5. Границы формата и этика — `Note`, всегда в потоке контента, не в подвале и не под аккордеоном.
6. Инвертированная полоса — не чаще одной на страницу.
7. Таблицы: только там, где данные действительно табличные; на мобиле — горизонтальная прокрутка с `min-w`. Сравнение «состояние человека → что нужно → наш ответ» на `/kursy` разложено в колонки-строки, а не в таблицу: так оно живёт на любой ширине.
8. Приоритет CTA: диагностика → бесплатное → продукты. На мобиле диагностика и библиотека доступны в два тапа с любой страницы (шапка + drawer).
9. Горизонтальная навигация раскрывается с `xl` (1280px): пять пунктов, бренд, переключатель палитры и CTA в строку раньше не помещаются и начинают переноситься.
10. Скрывая компонент по ширине, пишем `max-sm:hidden`, а не `hidden sm:inline-flex`: базовый `inline-flex` кнопки и безусловный `hidden` имеют одинаковую специфичность, и в сгенерированном CSS побеждает не тот, кто позже в атрибуте `class`.

## 10. Design QA checklist

- [ ] Первый экран: бренд крупнее заголовка, нет вторичного шума
- [ ] Все палитры проверены на странице: текст читаем, кнопки контрастны, иллюстрации в тон
- [ ] Тёмные палитры: инвертированные полосы не «выжигают» и не сливаются
- [ ] Нет сырых hex/oklch в компонентах — только токены
- [ ] Карточек нет там, где нет взаимодействия
- [ ] `prefers-reduced-motion`: нет сдвигов, контент виден сразу
- [ ] С выключенным JS контент виден полностью
- [ ] Клавиатура: меню, фильтры, диагностика, формы проходятся полностью, focus-ring виден
- [ ] Мобильные 360–430px: нет горизонтального переполнения, CTA в первом экране
- [ ] Границы формата и дисклеймеры заметны на продуктовых страницах
